Problem

当前只查 active cell 的直接 shapes，子 cell instance 中可见的金属会被判为空白；多层时还可能选中点击处不存在的层，或按 layout 顺序猜第一层。

Solution

把递归图形查询、可见层目录、Panel 选择和冲突策略集中到一个 deep module；未命中时明确标记 fallback 或 unresolved，不伪装成精确命中。

Deletion test

删除 resolver 后，递归查询、Panel 解析和仲裁会重新散落到每个点击模式；该 module 有真实 depth。

  • • locality：选层 bug 集中
  • • leverage：所有 marker 共用
  • • interface：测试一处决策
  • • 删除未调用旧扫描 implementation
KLayout 官方 Cell interface 已提供 begin_shapes_rec_touching/overlapping，并支持 DBox 微米坐标；仓库最低版本 0.28 满足其版本要求。

Problem

README、需求和激活提示都说 CUT 是“位置 + 方向”，但 implementation 与 CONNECT 一样，对两次点击都选层并保存 layer1/layer2。

Solution

共享鼠标捕获，隐藏模式差异；CUT 只给目标位置解析层，CONNECT 给两个电气端点解析层。旧坐标字段继续保留以避免破坏现有项目。

Deletion test

删除模式语义 module 后，点击角色判断会回到事件、marker、报表和转换代码，locality 明显丢失。

  • • locality：点击角色集中
  • • leverage：报表语义一致
  • • interface：模式测试可读
  • • 兼容旧 marker 数据
需要先确认生产语义：当前绘制 implementation 把 CUT 画成两点路径，而文档把它定义为中心 + 方向。这是领域决策，不应只靠重构猜测。

Problem

点击时立即把层变成显示字符串；“N/A”同时充当数据和值；名称改变会污染身份。多点 marker 的 XML 又完全不保存 point_layers。

Solution

marker 保存规范化层身份和可选名称/来源，Panel 与报表最后才格式化；序列化 adapter 读取旧字符串并写出稳定字段。

Deletion test

删除规范化 module 后，兼容解析、缺失值和显示格式会重新散落在 JSON、XML、Panel 与两套报表。

  • • locality：格式只在边缘
  • • leverage：保存与报表共用
  • • interface：缺失不再是假值
  • • 多点 XML 不再丢层

Top recommendation

先深化 Layer Resolver

它直接修复层级 GDS 中的漏检与错误 fallback，改动可限制在选层 module 内，兼容风险最低；完成后再用真实生产数据决定 CUT 是否从“两端点”恢复为“目标位置 + 方向”。

官方依据：KLayout Cell interface 的 recursive shape iterators，以及 LayerProperties 的 source_layer/source_datatype 专用属性。
